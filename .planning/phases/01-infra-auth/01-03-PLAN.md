1. apps/api/src/middleware/auth.ts 생성 (RESEARCH Pattern 2 기반):

   authenticateToken 미들웨어:
   - req.cookies.accessToken에서 JWT 추출 (httpOnly cookie)
   - jsonwebtoken.verify로 검증
   - 검증 실패(만료/무효) 시 401 반환: { error: '인증이 필요합니다' }
   - 성공 시 decoded payload를 req.user에 할당 (userId, email, role 포함)
   - Express Request 타입 확장: declare global로 req.user 타입 정의

   authorize 미들웨어 팩토리:
   - 허용 역할 배열을 받아 미들웨어 반환
   - req.user.role이 허용 목록에 없으면 403: { error: '권한이 없습니다' }
   - 온보딩 미완료(role === null) 상태도 처리

   generateTokens 유틸리티 함수:
   - access token: { userId, email, role } 페이로드, 15분 만료
   - refresh token: { userId, tokenType: 'refresh' } 페이로드, 7일 만료
   - 두 토큰을 { accessToken, refreshToken } 객체로 반환

   setTokenCookies 유틸리티 함수:
   - res.cookie로 accessToken, refreshToken 설정
   - 개발 환경: httpOnly true, secure false, sameSite 'lax' (localhost CORS 대응, RESEARCH Open Question 1)
   - 프로덕션: httpOnly true, secure true, sameSite 'strict'
   - maxAge: access 15분, refresh 7일

   clearTokenCookies 유틸리티 함수:
   - res.clearCookie로 accessToken, refreshToken 삭제

2. apps/api/src/middleware/rateLimit.ts 생성:
   - express-rate-limit로 loginLimiter 생성: 15분 윈도우, 최대 5회
   - 초과 시 429: { error: '로그인 시도가 너무 많습니다. 15분 후 다시 시도하세요' }

1. apps/api/src/routes/auth.ts 생성:

   **POST /register** (AUTH-01):
   - zod 스키마로 email(이메일 형식), password(8자 이상) 검증
   - 이미 가입된 이메일인지 확인 → 409: { error: '이미 가입된 이메일입니다' }
   - bcrypt.hash(password, 10)으로 해싱
   - users 테이블에 insert (role: null, isOnboarded: false)
   - generateTokens 호출 → refresh token DB 저장 → setTokenCookies
   - 201 응답: { user: { id, email, role: null, isOnboarded: false } }

   **POST /login** (AUTH-02):
   - zod로 email, password 검증
   - loginLimiter 미들웨어 적용
   - 이메일로 사용자 조회 → 없으면 401: { error: '가입되지 않은 이메일입니다' } (사용자 결정: 구체적 에러 메시지)
   - bcrypt.compare로 비밀번호 확인 → 불일치 시 401: { error: '비밀번호가 틀렸습니다' } (사용자 결정: 구체적 에러 메시지)
   - generateTokens → refresh token DB 저장 → setTokenCookies
   - 200 응답: { user: { id, email, role, isOnboarded } }

   **POST /refresh** (AUTH-03):
   - req.cookies.refreshToken에서 토큰 추출
   - jsonwebtoken.verify로 검증
   - DB에서 해당 refresh token 존재 여부 + 만료 확인
   - 기존 refresh token DB에서 삭제 (토큰 로테이션)
   - 새 토큰 쌍 발급 → 새 refresh token DB 저장 → setTokenCookies
   - 200 응답: { user: { id, email, role, isOnboarded } }
   - 실패 시 401 + clearTokenCookies

   **POST /logout** (AUTH-04):
   - req.cookies.refreshToken에서 토큰 추출
   - DB에서 해당 refresh token 삭제 (해당 기기만 로그아웃, RESEARCH Open Question 3 — 단일 기기 로그아웃)
   - clearTokenCookies
   - 200 응답: { message: '로그아웃 되었습니다' }

   **PATCH /onboarding** (AUTH-05):
   - authenticateToken 미들웨어 적용
   - zod로 role('student' | 'instructor') 검증
   - 이미 온보딩 완료된 사용자면 400: { error: '이미 역할이 설정되었습니다' }
   - users 테이블 업데이트: role, isOnboarded: true
   - 새 토큰 발급 (업데이트된 role 포함) → 쿠키 갱신
   - 200 응답: { user: { id, email, role, isOnboarded: true } }

   **GET /me** (AUTH-03):
   - authenticateToken 미들웨어 적용
   - DB에서 userId로 사용자 조회 (최신 정보)
   - 200 응답: { user: { id, email, role, isOnboarded } }
